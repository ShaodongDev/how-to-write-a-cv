# 新手如何写简历？

写一份好的简历是求职的入场劵。但判断一份简历的质量并不容易，一方面，我们自己写自己的简历，多少都一定会“自我感觉良好”，毕竟那是自己花了很长时间打磨出来的作品；另一方面，HR的视角跟求职者很不同，关注点也会不一样。更重要的是，似乎很难有评判标准让我门来审视自己的简历。本文自然有没有能力制定出这样的标准，但在总结经验和跟，尝试提出三个视角，来指导求职者写出一份面向HR的简历。



既然要面向 HR，我们必须首先搞清楚 HR 如何读一份简历。为此，我们不妨换位思考一下，假如我们是 HR 来读**一份**简历，会怎么读？

我们当然可以可以从头读到尾，认真看每一句话。可如果待处理的是几十份甚至上百份，阅读方式一定会改变。后者就是HR的工作。

因此，我们几乎可以肯定 HR 往往先扫读（scan），而不是阅读（read），更不是精读（scrutinize）。HR的视线会寻找职位、公司、行业以及职位描述里反复出现的关键词。只有看到相关信号，才会停下来细看；如果几秒之内没有找到，阅读很可能就结束了。

![](./assets/images/clipboard-1790405479762-u56z-1790405479766-5xww6nhc.png)

这不是招聘者不尊重候选人，而是工作量和专业能力决定了阅读方式。

于是，我们得到了第一个原则：

> **简历应该为扫读设计，而不是预设HR一上来就会逐字阅读。**

更精细一点，其实应该是为在显示器上的扫读而设计，这本质上跟我们浏览一个网页没什么不同。

适合在显示器上扫读的排版，主要依赖三个朴素的原则：邻近、对齐、重复。

邻近：属于同一组的信息应该靠近，不同组之间应该拉开。同一段工作经历中的公司、职位、时间和项目符号要形成一个视觉整体；两段经历之间的距离应该大于同一段内部的行距；教育、工作、项目和技能等板块之间，则需要更明显的分隔。即使暂时看不清文字，读者也应当能通过空间判断信息分组。

对齐：同一类信息应该共用一条左/右边线，公司名和职位采用稳定的层级，日期统一放在右侧。读完第一段经历后，读者的眼睛会形成预期：去哪里找公司，去哪里找时间，去哪里找成果。后面的版面不要让他重新学习。

重复：邻近和对齐规则建立后，就重复使用。相同层级使用相同字号，相同类型的日期采用相同格式，项目符号、缩进和行距保持一致。

至于颜色、图标、技能进度条和复杂的多栏设计，要谨慎使用。它们可能好看，却也可能抢走注意力、制造难以比较的尺度，甚至影响招聘系统解析文本。对大多数岗位而言，清楚、稳定、可复制的版式已经足够。





请注意，“为扫读设计”并不只是排版问题。如果最关键的经历藏在第二页末尾，即使字体再清楚，对方也可能看不到；如果一句话写了四行，却始终没说产出了什么，对方即使看到了，也无法判断。

为了进一步说明，我们虚构一位候选人小林。她想申请内容运营岗位，曾经经营过学校社团的公众号。最初，她这样写：

> 负责学校公众号的日常运营，参与内容策划、文章撰写和发布工作，取得了良好效果。

这句话的问题在哪里？每个词都认识，语法也完全正确，可读完以后，我们仍不知道：她写了多少篇文章？面向多少读者？“参与”到什么程度？所谓“良好效果”究竟有多好？

我们先把这个例子留在这里。要改好它，还需要补齐几个概念。

## 匹配：先证明你是“相关的人”

一份 CV 最先要解决的，不是“我有多优秀”，而是“我的优秀和这个岗位有什么关系”。

假设小林还拿过校级羽毛球比赛第三名。这个成绩当然很好，也真实地证明了她投入过时间、接受过训练。但对于内容运营岗位，它大概率不如公众号经历重要。

这不是说羽毛球经历没有价值，而是说：**价值永远存在于具体目标中。**

同样一块木头，在家具厂是原料，在餐厅是燃料，在博物馆也许是文物。离开用途讨论它“有没有价值”，通常得不到有意义的答案。

CV 也是这样。不存在一份脱离岗位、对所有招聘者都同样优秀的 CV。市场、产品、算法和财务岗位寻找的信号不同；即使岗位名称相同，两家公司关心的业务和工具也可能不同。

因此，写 CV 的第一步其实发生在文档之外：读职位描述。

### 职位描述不是广告，而是题目

职位描述，也就是常说的 JD（Job Description），通常会告诉你四类信息：

- 要解决什么问题；
- 要承担哪些任务；
- 要使用哪些技能或工具；
- 什么经历会被优先考虑。

你可以把它们整理成一张简单的证据表：

| 岗位需要什么 | 我有什么证据        | 证据够不够具体     |
| ------ | ------------- | ----------- |
| 内容策划   | 规划过社团公众号选题    | 还缺选题数量和周期   |
| 文案写作   | 独立撰写并发布文章     | 还缺文章数量和阅读数据 |
| 数据复盘   | 分析后台数据并调整选题   | 还缺调整后的结果    |
| 跨部门协作  | 与设计、活动组共同发布内容 | 还缺协作规模和个人职责 |

这张表会暴露三个结果：

1. 有些要求，你已经有直接证据；
2. 有些要求，你做过相关的事，只是没有说清楚；
3. 有些要求，你确实没有证据。

前两类可以通过写作解决，第三类不行。CV 能整理证据，却不能创造事实。这条边界非常重要，我们后面还会回来。

### 确保相关、凸显相关、解释相关

提高匹配度，大致有三层。

第一层是**确保相关**。与岗位无关的内容应当压缩，必要时删除。CV 不是自传，没有义务保存每一段经历。

第二层是**凸显相关**。最相关的板块和信息应该更靠前。CV 没有规定教育背景必须排第一，也没有规定项目经历只能放在工作经历后面。先放什么，应当由“什么最能证明你适合这个岗位”决定。

第三层是**解释相关**。很多经历本来有关，只是联系没有被写出来。比如“维护社团公众号”听起来像一项校园杂务；如果把选题、受众、发布频率和数据结果讲清楚，它就会变成一段内容运营证据。

这不是编造相关性，而是把真实存在的相关性从水下提到水面。

## 证据：形容自己没有什么用

现在，我们可以继续处理小林的那句话了。

原句是：

> 负责学校公众号的日常运营，参与内容策划、文章撰写和发布工作，取得了良好效果。

假如小林补充了一些事实：她连续运营了一个学期；独立规划了 12 个选题；写了 8 篇文章；通过后台数据发现“校友故事”阅读表现最好，于是增加了同类内容；调整后，单篇平均阅读量从 800 提高到 1,300。

那么这段经历可以写成：

> 分析公众号历史阅读数据，独立策划 12 个选题并撰写 8 篇文章；根据高表现内容增加“校友故事”选题，使单篇平均阅读量由 800 提升至 1,300。

前后两句话描述的是同一段经历。后一种写法却让人看见了四样东西：

- **动作**：分析、策划、撰写、调整；
- **对象**：公众号数据、选题和文章；
- **规模**：12 个选题、8 篇文章；
- **结果**：平均阅读量提升 500，约 62.5%。

这四类信息组成了一条最基本的证据链：

> **在什么情境下，用什么方法，做了什么，产生了什么结果。**

有些人喜欢把它记成 STAR：Situation（情境）、Task（任务）、Action（行动）、Result（结果）。名字并不重要，重要的是让招聘者能够从结果反推你的能力。

### 数字为什么有用？

常见的建议是“CV 一定要量化”。这句话又对，又不完全对。

数字的作用不是装饰，也不是让一件普通的事显得宏大。它真正的作用是减少歧义。

“组织了一场大型活动”中的“大型”，可能是 50 人，也可能是 5,000 人；“处理大量数据”中的“大量”，对 Excel 用户和分布式系统工程师完全不是一回事。换成“协调 6 个社团，为 420 名参与者组织活动”或者“清洗 12 万条交易记录”，读者才能建立尺度。

可以量化的不只有收入增长。还有：

- 人数、客户数、用户数；
- 文档、文章、功能或项目的数量；
- 数据规模、预算和覆盖范围；
- 周期、频率、提前量和节省的时间；
- 转化率、准确率、缺陷率和满意度；
- 合作的团队、地区、语言或利益相关方数量。

当然，并不是每句话都必须塞进百分比。如果结果无法可靠量化，就写清楚具体产出，例如“形成需求文档并被产品团队用于下一版本排期”，也比“有效支持产品迭代”更可信。

所以，更准确的原则不是“数字越多越好”，而是：

> **数字 > 含糊的形容词；具体产出 > 抽象的自我评价。**

### 技能只有被使用过，才像技能

“熟练掌握 Excel、Python、SQL、Photoshop、Premiere、Figma……”

这样的技能栏很常见。问题是，“熟练”无法校准。有人会写几个公式就认为自己熟练 Excel，有人做完复杂的数据模型仍只肯写“掌握”。招聘者很难仅凭一个词判断。

更强的证据，是让技能出现在经历里：

> 使用 SQL 清洗并合并 12 万条订单记录，在 Tableau 搭建周报看板，将人工汇总时间从 3 小时缩短至 20 分钟。

这句话不仅说“会 SQL 和 Tableau”，还说明了用它们处理什么问题、处理多大规模，以及产生什么价值。

技能栏仍然可以保留，因为它便于扫读和关键词检索。但它应该像目录，真正的内容要能在工作、项目或研究经历中找到。

## 表述：你不在场，无法补充解释

CV 是一种很特殊的沟通。

面试时，对方听不懂可以追问：“你说负责项目，具体负责哪一部分？”你也能根据对方的表情换一种说法。但 CV 发出后，你通常不在场。招聘者不会因为一句话含糊，就来信邀请你解释清楚再重新判断。

因此，CV 是一次从读者出发的单向沟通。

写完每条经历，可以连续追问：

1. “负责”“参与”“协助”之后，我究竟做了什么？
2. 工作对象是什么，规模有多大？
3. 我用了什么方法、工具或专业知识？
4. 最后交付了什么，改变了什么？
5. 这件事为什么能证明我适合目标岗位？

很少有一句空话经得起这五个问题。

例如：

> 协助团队完成用户调研。

追问后可能变成：

> 设计 18 题用户问卷并访谈 12 名付费用户，归纳 3 类流失原因，形成调研报告供产品团队确定下一季度优化优先级。

又例如：

> 负责自动化测试，提高了工作效率。

追问后可能变成：

> 使用 Python 为登录与支付流程编写 46 个自动化测试用例，将版本回归测试时间从 2 天缩短至 5 小时。

如果某个数字或结果并不存在，就不要为了句式完整而编造。可以诚实地写动作、方法和交付物。经不起面试追问的“优化”，不是优化。

### 一条经历先写什么？

人们阅读长句时，注意力不会平均分配。越靠前的信息越容易在扫读中被捕捉。因此，同一条项目符号里，最相关的动作和关键词应该尽量提前。

申请数据岗位时，与其写：

> 为支持部门日常工作，参与销售资料整理，并使用 Python 对数据进行了处理。

不如写：

> 使用 Python 清洗 5 万条销售记录，统一 4 个区域的字段格式，为月度经营分析提供数据集。

两句都没有撒谎，但第二句更早交代了工具、对象和规模。招聘者不必读到句尾，才发现这段经历与岗位有关。

### 删除也是写作

很多人修改 CV 时只会增加：补一段总结，加一项技能，再塞进两个奖项。结果每条信息都在争夺注意力，真正重要的证据反而被淹没。

摘要之所以是摘要，正在于它放弃了什么。

以下内容通常值得压缩或删除：

- 与目标岗位无关、又不能证明通用能力的旧经历；
- 没有证据支撑的“责任心强、学习能力强、善于沟通”；
- 过多且区分度很低的校内奖项；
- 完整住址、身份证号、婚姻状况等不必要的个人信息；
- 与经历重复、只换了一种说法的技能和总结；
- 占据大量空间，却无法说明个人贡献的项目背景。

删掉一句话的判断标准很简单：如果它消失以后，招聘者对“你为什么适合这个岗位”的理解没有任何损失，那它很可能本来就不该占据这个位置。

## 排版：给信息修路

走到这里，我们终于可以谈模板了。

排版很重要。只不过它的作用不是把普通经历装饰成优秀经历，而是让已经存在的证据顺利抵达读者。

可以把一份 CV 想成一座机场。公司、职位、时间、成果是乘客；字号、间距、对齐和粗体是标识系统。标识做得好，乘客能快速找到登机口；标识混乱，再好的航班也可能被错过。但如果根本没有航班，多装几块漂亮的指示牌也没用。

适合扫读的排版，主要依赖三个朴素的原则。

### 邻近

属于同一组的信息应该靠近，不同组之间应该拉开。

同一段工作经历中的公司、职位、时间和项目符号要形成一个视觉整体；两段经历之间的距离应该大于同一段内部的行距；教育、工作、项目和技能等板块之间，则需要更明显的分隔。

即使暂时看不清文字，读者也应当能通过空间判断信息分组。

### 对齐

同一类信息应该待在相同的位置。

板块标题共用一条左边线，公司名和职位采用稳定的层级，日期统一放在右侧。读完第一段经历后，读者的眼睛会形成预期：去哪里找公司，去哪里找时间，去哪里找成果。后面的版面不要让他重新学习。

### 重复

一旦建立规则，就持续使用。

相同层级使用相同字号，相同类型的日期采用相同格式，项目符号、缩进和行距保持一致。这里的重复不是乏味，而是一种承诺：读者在一个位置学会的规则，在其他位置仍然有效。

至于颜色、图标、技能进度条和复杂的多栏设计，要谨慎使用。它们可能好看，却也可能抢走注意力、制造难以比较的尺度，甚至影响招聘系统解析文本。对大多数岗位而言，清楚、稳定、可复制的版式已经足够。

## 顺序：为什么不是先改排版？

现在，请把前面出现的几个概念重新连起来：

- 招聘者需要在有限时间内判断风险；
- 因此，他先寻找与岗位有关的信号；
- 信号必须由真实经历提供；
- 经历需要被组织成具体证据；
- 证据还要通过版面被快速发现。

这样一来，修改 CV 的顺序就很清楚了：

> **匹配 > 表述 > 排版**

可以用排除法验证。

排版不可能排第一。它能让信息更容易被找到，却不能让一段无关经历突然与岗位有关。

表述也不可能排第一。如果小林申请的是会计岗位，即使把公众号阅读量写得再精确，它仍然不是最核心的证据。

匹配应该排在最前面。先决定要证明什么、选择哪些材料，再把材料写清楚，最后修整它们出现的方式。顺序一旦反过来，人就很容易在字体和措辞上反复消耗，却始终没有回答“你到底想找什么工作”。

不过，这还不是完整答案。

## 经历：CV 能写出的，终究是你做过的事

假设小林从未运营过公众号，没有写过文章，也没有研究过用户。我们能否通过关键词、数字和精美排版，替她写出一份有说服力的内容运营 CV？

不能。

最多只能把已有材料重新组合，找出一些可迁移的能力；如果相关证据根本不存在，写作就到达了边界。

这也是为什么，本文用了很大篇幅讲“怎么呈现”，最后却必须回到“做过什么”。CV 更像一棵树当季结出的果实：纸面上的公司名、项目、数字和技能都看得见；看不见的根系，则是你花过的时间、解决过的问题、做失败的尝试、与人协作的经验，以及由此形成的判断力。

根系太浅，仅靠擦亮果皮并不能让果实变得饱满。

因此，完整的优先级是：

> **经历 > 匹配 > 表述 > 排版**

短期内要投递，可以做的是从右边三项中优先解决最重要的：先依据 JD 重新取舍和排序，再逐句降低不确定性，最后修整版面，把已经拥有的证据尽可能清楚地呈现出来。

长期内，更重要的工作则从前往后进行：先确定大致方向，再通过项目、实习、研究、作品或真实问题积累相关经历；从经历中记录成果和尺度；投递时选择与岗位最相关的证据；最后才把它们放进一页或两页纸里。

## 最后检查一次

在导出 PDF 之前，不妨按下面的顺序问自己。

### 经历

- 我是否真的做过目标岗位看重的事？
- 重要项目有没有留下作品、数据、文档或其他可验证的结果？
- 如果证据不足，下一段经历应该刻意补什么？

### 匹配

- 这份 CV 面向哪个明确岗位？
- 最相关的经历是否排在最容易被看到的位置？
- 每个主要板块都在帮助招聘者判断岗位适配度吗？

### 表述

- 每个项目符号是否写清了动作、对象、方法、规模或结果？
- 模糊形容词能否换成数字或具体产出？
- 技能是否能在实际经历中找到证据？
- 所有内容是否真实，并经得起面试继续追问？

### 排版

- 公司、职位、时间和成果能否在几秒内被找到？
- 邻近、对齐和重复是否形成了稳定规则？
- 字号、行距、颜色和装饰是否在帮助阅读，而不是争夺注意力？
- 导出的 PDF 能否正常复制文字，链接是否可用，文件名是否专业？

如果这些问题都有答案，一份 CV 就基本完成了。

它未必拥有最漂亮的模板，也未必罗列了人生中的每项成就。但招聘者能迅速明白：你想做什么，你做过什么，以及为什么值得进入下一轮。

这就够了。CV 本来就不负责替你得到一份工作，它只负责把你送到下一场对话里。
